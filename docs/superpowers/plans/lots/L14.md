# L14 — Documentation : plan du lot

> **For agentic workers:** lot de documentation, sans code. Pas de TDD : la vérification porte sur la cohérence avec les contrats et la validité des liens.

**Goal :** fournir la documentation d'installation, d'enrôlement, de politique, d'exploitation, de sécurité, d'API, de CLI, de MCP et de migration, alignée sur les contrats figés (plan maître §3, ADR 0001–0010), et mettre à jour les README et `CONTRIBUTING.md`.

**Sources :** `docs/cahier-des-charges.md`, `docs/superpowers/specs/2026-10-30-agents-firewall-design.md`, `docs/superpowers/plans/2026-10-30-agents-firewall-v1.md`, `docs/adr/*.md`, brief des lots L11/L12 (enrôlement, déploiement).

## Règles de rédaction

- Français soigné, phrases courtes, exemples concrets et génériques (`internes`, `clients`, `mon-agent`, `api.exemple.com`). Rien de propre à Pulse myIT dans le cœur ; Daniel et l'egress-guard n'apparaissent que dans `docs/migration-egress-guard.md`.
- Toute commande, route, variable ou chemin cité vient du plan maître, d'un ADR ou du brief de lot. Ce qui dépend d'un lot non fusionné est marqué « (à venir) ». Les options exactes de la CLI non encore figées ne sont pas inventées : on donne la forme prévue et on renvoie à `afw <commande> --help`.
- Liens relatifs uniquement vers des fichiers présents dans le dépôt ; un fichier pas encore livré (ex. `docs/api/openapi.yaml`, `demo/up.sh`) est cité en `code`, sans lien.
