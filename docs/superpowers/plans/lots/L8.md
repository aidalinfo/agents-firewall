# L8 — `afw-client` + CLI `afw` : plan détaillé

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Étapes en cases à cocher.

**Goal :** client Rust typé de l'API `/api/v1` (`afw-client`) et CLI `afw` couvrant tout le périmètre de la console,
enrôlement compris (EF-40, EF-41, EF-42, EF-45, EF-60, EF-64).

**Contrat :** `docs/api/openapi.yaml` (source de vérité) et DTO `afw_core::api`. L'API est développée en parallèle
(L7a/b/c) : tout est testé contre un faux serveur axum (`afw_client::fake::FakeApi`, feature `fake`) qui sert des
réponses construites à partir des types `afw-core` (donc conformes aux schémas générés). ADR : 0025.

**Architecture :**
- `afw-client` : `AfwClient::new(base_url, token, Interface)` (reqwest + rustls, CA additionnelle possible) ;
  en-têtes `Authorization: Bearer`, `X-Afw-Interface`, `X-Afw-Session` quand une session est active ; une méthode
  par opération ; erreurs `ClientError::Api { status, problem }` ; SSE `logs/stream` ; décodage tolérant des vues
  de règles (`RuleEntry`) et de la publication 201/202 (`PublishOutcome`).
- `afw-cli` : bibliothèque (`afw_cli::run`) + binaire `afw` (clap derive). Sortie tableau (colonnes par pointeurs
  JSON) ou `--json`. Configuration `~/.config/afw/config.toml` (0600, jeton jamais affiché). Résolution nom → id.
  Mutations dans la session courante (`GET /sessions/current`), ouverte automatiquement si besoin.
