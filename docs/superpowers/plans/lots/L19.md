# Lot L19 — Finitions après la recette

Objectif : corriger les écarts relevés par la recette (ADR 0027) et rafraîchir la documentation.
Décisions : [ADR 0028](../../../adr/0028-mode-de-refus-et-ordre-de-l-audit.md).

## Tâches (TDD)

1. **Passerelle, CONNECT refusé** — tests `crates/afw-gateway/tests/bypass.rs`
   (`connect_to_denied_host_refused`, `denied_https_gets_explicit_403_message`,
   `denied_tcp_is_reset_and_logged`) : application `https`, port demandé, `deny_mode`, en-tête
   `X-Agents-Firewall-Reason`. Puis `Flow::emit_deny(&Decision, DenyMode)` sur chaque refus.
2. **Contrat** — `FlowEvent.deny_mode: Option<DenyMode>` (additif) dans `afw-core`, schémas et
   OpenAPI régénérés (`AFW_UPDATE_SCHEMAS=1`), `agent_message` de l'API suit `deny_mode`.
3. **Audit** — test `crates/afw-api/tests/audit_api.rs` (décroissant par défaut, `order=asc`,
   curseur dans les deux sens, `order` invalide = 400) ; API, client, CLI `--order`, MCP `order`.
4. **MCP** — tests contre la vraie API (`crates/afw-mcp/tests/real_api.rs`) : `discard_session`
   abandonne vraiment, et ignore une session fermée ailleurs ; test API `logs.rs` : l'accès aux
   contenus est tracé avec l'interface de l'appelant, jamais pour `mcp_agent`.
5. **Console** — `denyKind`/`flowTarget` (tests unitaires), libellé du refus, destination demandée,
   audit le plus récent d'abord, libellé `afw-mcp` ; `pnpm gen:api`.
6. **Documentation** — index des ADR complet, mentions « à venir » retirées après vérification
   contre le code, démarrage rapide exact dans les README.
7. **Démo** — `demo/up.sh`, `demo/scenarios/run-all.sh`, `demo/screenshots.sh` pour régénérer
   `docs/rapport/captures/` et `docs/rapport/recette/results.*`, puis `demo/down.sh`.
