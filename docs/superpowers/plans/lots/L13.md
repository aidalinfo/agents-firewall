# Lot L13 — Recette de bout en bout, captures et mesures

**But.** Faire tourner l'environnement de démo complet (`demo/`, lot L12) sur le code fusionné dans `dev`, jouer
tous les scénarios en PASS réel, capturer chaque écran de la console avec des données issues des scénarios, mesurer
la latence et les délais du journal, et produire les preuves versionnées pour le rapport final.

**Architecture.** Rien de nouveau dans le produit : corrections d'intégration (petites, testées) là où la démo révèle
un écart entre les lots ; scénarios ajoutés ou corrigés dans `demo/scenarios/` ; captures par une spec Playwright
(`console/e2e/recette.spec.ts`, ignorée hors recette) lancée par `demo/screenshots.sh` dans l'image Playwright
épinglée, sur le réseau `publish` de la démo. Décisions : ADR 0027.

## Tâches

1. **Démarrage.** Construire les images une par une (`CARGO_BUILD_JOBS=3`), `demo/up.sh --no-build`, corriger chaque
   blocage d'intégration :
   - API : `AFW_PKI_DIR` par défaut sous `AFW_STATE_DIR` (utilisateur non root) et export de la CA console
     (`AFW_CONSOLE_CA_EXPORT`, supposé par compose et Helm) — tests unitaires d'abord ;
   - compose/Helm : `AFW_GW_SERVER_NAMES` (et non `AFW_PUBLIC_HOSTNAMES`, jamais lu) ; console en même origine
     (`NUXT_API_PROXY_TARGET`) ;
   - `up.sh` : recharger le jeton du plugin écrit dans un sous-shell avant de démarrer daniel-bot.
2. **Scénarios 01–17 en PASS.** Corriger les scénarios dont l'attente ne correspond pas à la sémantique réelle
   (refus HTTPS au `CONNECT`, nom du flux = `Host` en clair, poignée de main locale de l'écoute transparente),
   sans affaiblir la preuve (témoins positifs, preuve de non-réception chez la cible).
3. **Scénarios ajoutés.** 18 passerelle arrêtée ; 19 console injoignable ; 20 mesures du journal ; 12 latence
   refaite (HTTPS inspecté, connexion nouvelle et réutilisée, 5 passes, médiane).
4. **Captures.** 1440×900, thèmes sombre et clair pour les écrans principaux, données réelles ; « Autoriser » depuis
   la console chronométré jusqu'au passage effectif de l'agent.
5. **Preuves.** `docs/rapport/recette/` (results.md/json, latency.json, measures.json, chronométrage UI),
   `docs/rapport/captures/` + README légendé ; tableau critère §8 → preuve dans le rapport de lot.
6. **Après fusion de la CLI (L8/L9).** Rebaser, rejouer 10 (afw-mcp) et 11 (Hermes en une commande) avec la CLI,
   compléter l'audit avec l'interface `cli`.
